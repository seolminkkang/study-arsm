# 실험 기록 규칙

## 독자 전제 — 매번 확인할 것

이 vault를 읽는 두 사람은 **비전공자이고 실무 경험이 없다.**
운영체제·네트워크·DB를 훑어본 정도이고, 장애를 겪어본 적이 없다.

따라서 노트를 쓸 때:

- 용어는 처음 나올 때 풀어쓴다. 약어는 한 번 펼친다
- "당연히", "아시다시피", "보통 이렇게 합니다"를 쓰지 않는다.
  실무 관례를 전제로 깔면 두 사람 다 모른다
- "이런 상황 겪어보셨을 텐데" 류를 쓰지 않는다. 겪은 적이 없다
- "많이 느려졌다"가 아니라 "p95가 40ms → 480ms"로 쓴다
- 문장 수준은 `technical-writing-guide`의 **Step 3**을 따른다
  (주체 분명, 한 문장 한 생각, 구체적 수치, 자연스러운 한국어, 일관된 용어).
  Step 1의 문서 유형 분류는 적용하지 않는다

## 어디에 쓰는가

먼저 이 판단을 한다. 층을 잘못 고르면 나중에 무엇이 사실이고
무엇이 해석인지 구분할 수 없게 된다.

| 내용 | 위치 | 수정 |
|---|---|---|
| k6 출력, EXPLAIN 결과, 로그, 캡처 | `vault/raw/` | **금지** |
| 그 결과에 대한 해석 | `vault/experiments/` | 가능 |
| 반복 등장하는 개념 | `vault/concepts/` | 가능 |
| 회차에 있었던 일 | `vault/sessions/` | 가능 |
| 공개용으로 다듬은 글 | `vault/output/` | 가능 |

`raw/` 파일명은 `YYYY-MM-DD_exp-NNN_설명.txt` 형식.
같은 실험을 다시 돌렸으면 기존 파일을 고치지 말고 새 파일을 추가한다.

`raw/`는 요약해서 옮기지 않는다. 도구 출력을 그대로 붙인다.
실행계획 읽는 법을 익히는 게 3장의 절반이고, 두 사람이 원본을 직접 봐야 한다.

## frontmatter 필드는 고정

중간에 필드명을 바꾸면 대시보드에서 과거 노트가 통째로 사라진다.

**실험 노트** (`experiments/exp-NNN-제목.md`)
```yaml
---
id: exp-001
title: 오프셋 페이징과 응답 시간
chapter: [2, 3]
status: planned | running | done | failed
date: 2026-09-06
commit: a3f9c21
raw: ["2026-09-06_exp-001_k6.txt"]
conclusion: 한 줄. 실측 근거가 있을 때만 채운다
tags: [experiment]
---
```

**개념 노트** (`concepts/개념명.md`)
```yaml
---
title: 커넥션 풀
chapter: [2]
tags: [concept]
---
```

**회차 노트** (`sessions/YYYY-MM-DD-N회차.md`)
```yaml
---
date: 2026-09-06
session: 1
host: 설민
chapters: [2, 3]
experiments: [exp-001, exp-002]
tags: [session]
---
```

## 실험 노트 본문

```markdown
## 가설
## 조건
- 앱: CPU n, mem n / DB: CPU n
- 데이터: 테이블명 n건, 분포
- 변수: 무엇을 바꿨는가

## 예측
| 사람 | 예측 | 근거 |
|---|---|---|

## 결과
[[raw 파일 링크]] 참조. 여기엔 요약 수치만.

## 예측과의 차이
## 남은 질문
- #question ...
```

**"예측" 섹션은 절대 채우지 않는다.** 사람이 쓸 자리다.
빈 채로 두고 "여기는 직접 채우세요"라고 알린다.

**"예측과의 차이"가 이 노트의 핵심이다.** 결과만 적힌 노트는
6개월 뒤에 읽어도 아무것도 복원되지 않는다. 무엇을 틀렸는지가 적혀 있어야
그때의 사고가 되살아나고, 면접에서 꺼낼 수 있는 것도 이 부분이다.

## 개념 노트 본문

```markdown
## 언제 마주쳤나
[[exp-001]]에서 ... (실험 링크 필수)

## 지금 이해한 것
(2~3줄. 길어지면 챕터 요약으로 변질된다)

## 아직 모르는 것
- #question ...
```

**"아직 모르는 것"을 비워두지 않는다.** 비전공자 스터디에서 가장 위험한 것은
애매하게 이해한 것을 이해한 것으로 넘기는 일이다.
명시적으로 적어두면 나중에 다시 마주쳤을 때 "그때 미뤄둔 거네"가 된다.

## 링크 규칙

옵시디언 그래프가 의미를 가지려면 링크가 일관돼야 한다.

- 실험 노트 → 등장한 개념을 전부 `[[개념명]]`으로 건다
- 개념 노트 → 마주친 실험을 `[[exp-NNN]]`으로 건다 (양방향)
- 회차 노트 → 그날의 실험을 전부 링크
- 같은 개념은 항상 같은 이름으로 쓴다. "커넥션 풀"과 "connection pool"을 혼용하지 않는다

개념 노트를 따로 두는 이유: 커넥션 풀은 2장(DB 커넥션 풀), 3장(DB 최대 연결 개수),
4장(HTTP 커넥션 풀)에 모두 나온다. 챕터별로 관리하면 같은 개념이 세 군데 흩어진다.
개념 노트 하나에 백링크가 모여야 "이 개념이 책 전체에서 어떻게 반복되는가"가 보인다.

## 쓰지 않을 것

- 실측 근거 없는 `conclusion`. 근거가 없으면 본문에 `#가설`로 남긴다
- 사람의 예측
- 책 본문을 그대로 옮긴 요약 (저작권 문제. 공개 저장소다)
- "아마 ~일 것이다" 형태의 추정을 결론처럼 서술하는 것

- 2026-09-06 exp-001 완료. 오프셋 99990에서 p95 12배 증가. [[exp-001]]
