# 진행 상황 파악

## 전제 — 책 내용은 모른다

이 저장소를 읽는 AI는 책 본문을 갖고 있지 않다.
알 수 있는 것은 **목차와 각 절의 진행 상태**뿐이다.

따라서 "이 절은 이런 내용이니 이렇게 실험하자"는 제안을 하지 않는다.
대신 "이 절이 아직 `#미실험`이다. 어떤 내용인지 알려달라"고 요청한다.

책 내용은 사용자가 던져주는 것이지, 추측하는 것이 아니다.

## 독자 전제

두 사람 다 **비전공자이고 실무 경험이 없다.**
운영체제·네트워크·DB를 훑어본 정도이고, 장애를 겪어본 적이 없다.

다음 할 일을 제안할 때 이 점을 반영한다.

- 실무 관례를 전제로 한 제안을 하지 않는다.
  "보통 이렇게 합니다"가 근거가 될 수 없다
- 소요 시간을 넉넉하게 잡는다. 처음 해보는 작업이 대부분이다
- 한 번에 한 가지만 제안한다. 병렬로 여러 개를 던지면 판단이 막힌다
- 선택지를 줄 때는 각각이 무엇을 확인하기 위한 것인지 명시한다

## 읽는 순서

1. `vault/progress.md` — 책 전체 목차와 각 절의 상태
2. `vault/log.md` — 시간순 처리 이력
3. `vault/experiments/` 의 frontmatter — `status`, `conclusion`
4. vault 전체의 `#question`, `#가설`, `#미실험` 태그

## 출력 형태

### "어디까지 했지" 요청

```
완료: 2장 (A급 2 / B급 3 / 미실험 8)
진행 중: 없음
다음 회차: 4장 (Host: 팀원)

미해결 질문 5개:
- [[exp-001]] HikariCP pending이 0인데 왜 p95가 나빠졌나
- ...
```

### "다음에 뭐 해야 해" 요청

```
1. 지금 열려 있는 질문 중 실험 가능한 것
2. 아직 손 안 댄 절 (progress.md의 #미실험)
3. 각각 왜 지금인지, 예상 소요 시간
```

**실험 결과를 예측하지 않는다. 조건을 설계하지도 않는다.**
무엇을 다룰지 고르는 것까지만 한다.

### "회차 정리" 요청

1. 이번 실험 노트의 "예측과의 차이"에서 아직 설명되지 않은 것을 질문으로 추출
2. **이번 결과가 과거 결론을 무효화하거나 수정하는지 확인** — 있으면 해당 노트 링크와 함께 지적
3. `sessions/` 노트 초안 작성
4. 새로 등장했는데 `concepts/`에 없는 개념 목록
5. `progress.md` 상태 갱신, `log.md`에 한 줄 추가

2번이 이 skill의 존재 이유다. 회차가 쌓이면 과거 결론이 틀렸던 게 드러나는데,
사람은 그걸 잘 못 찾는다. "3회차에서 커넥션 풀이 병목이라고 했는데
5회차 결과를 보면 아니었다"를 짚어주면 vault가 쌓이기만 하는 게 아니라
자기 수정을 하게 된다.

## 하지 않을 것

- 결론을 대신 쓰기 (초안까지만)
- 책 내용 추측해서 채우기
- 미해결 질문을 임의로 닫기
- `raw/` 수정
