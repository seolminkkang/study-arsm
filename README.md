# backend-study

『주니어 백엔드 개발자가 반드시 알아야 할 실무 지식』(최범균, 한빛미디어) 2인 스터디 기록.

책을 읽고 요약하는 스터디가 아니라, **책이 말한 것을 실제로 측정해서 확인하는** 스터디입니다.

## 누가 하는가

백엔드 비전공 개발자 두 명입니다. 운영체제와 네트워크는 훑어본 정도이고,
실무에서 장애를 겪어본 경험은 없습니다. 스프링으로 기능 구현은 해봤습니다.

그래서 "경험으로 아는 것"에 기대지 않고 **직접 만들어서 측정하는 방식**을 택했습니다.
이 책이 산술 모델을 명시적으로 제시하기 때문에(`풀 크기 / 쿼리 시간 = 최대 TPS`)
경험이 없어도 예측과 검증이 가능합니다.

## 구조

```
vault/   옵시디언 vault — 실험 기록, 개념 노트, 회차 기록
lab/     실험 환경 — 스프링 앱, 시딩 SQL, k6 스크립트
```

## 방식

| 역할 | 하는 일 |
|---|---|
| Host | 책을 미리 읽고 **관찰 조건을 설계**한다. 당일 전에 혼자 돌려본다 |
| Challenger | 책을 안 읽고 온다. 관찰하고, 예측하고, 틀리고, 그 다음에 읽는다 |

매 회차 번갈아 맡습니다.

회차 흐름: **관찰 → 개념 도입 → 예측 → 실행 → 정리**

예측이 개념 도입 뒤에 오는 이유가 있습니다.
어휘가 없는 상태에서는 예측 자체가 불가능하기 때문입니다.
현상을 먼저 보고, 이상한 점을 찾고, 거기에 이름을 붙이면
개념이 정의가 아니라 **이름 붙이기**로 들어옵니다.

## 원칙

- 실측 없이 결론을 쓰지 않는다. 추측은 `#가설`로 남긴다
- 예측은 사람이 쓴다. 틀리는 순간이 학습이 일어나는 유일한 지점이다
- `vault/raw/`의 측정 원본은 수정하지 않는다
- 모르는 것은 모른다고 적는다. 개념 노트의 "아직 모르는 것"을 비워두지 않는다
- 책 요약을 공개하지 않는다. 공개하는 것은 "재봤더니 이랬다"
