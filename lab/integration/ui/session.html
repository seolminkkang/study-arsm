              기록과 추가 관찰
              서비스 값은 Prometheus와 실제 리뷰·지급 API에서 읽습니다. 더 자세한 시계열은 실행자 노트북의 Grafana에서 볼 수 있지만, 실습 중 반드시 열 필요는 없습니다.
              새 세션은 이전 기록이나 DB를 지우지 않습니다. 다운로드에는 두 사람의 메모와 실습 데이터가 포함됩니다.
              

              처음부터 다시 돌려보고 싶다면
              

              기존 영화 실습 DB는 그대로 둡니다. 아래 초기화는 별도 arsm-integration 환경의 리뷰·지급·배치·CDC 실습 데이터를 비웁니다. 이전 실험 기록과 백업 파일은 남습니다.
              

              이번 실험 초기화 · 지워지는 범위 확인

              1. A·B를 먼저 중지메모리에 남은 작업은 폐기합니다. 다른 터미널의 부하 테스트나 수동 요청은 먼저 직접 중단해주세요.
                2. 

              2. 전용 DB 백업 후 실습 8개 테이블 비우기review.reviews, review.outbox, review.batch_received, review.cdc_source, review.cdc_target, review.cdc_seen, points.point_grants, points.backup_grants의 모든 행을 비웁니다. 직접 넣은 실험 데이터도 포함합니다. 백업 실패 시 삭제하지 않습니다. A·B·대체 제공자를 먼저 멈춥니다. 큐는 비어 있고 소비자는 정지해야 하며, 미완료 CDC 슬롯이 있으면 초기화를 거절합니다. 먼저 마무리 단계를 실행하세요. 배치 파일·기록은 남습니다.
                3. 

              3. 기본 실행 설정으로 재시작HTTP 풀 2 · DB 풀 4 · 획득 대기 500ms · 연결/응답 대기 1000ms로 A·B를 다시 띄우고 새 세션의 준비 단계로 돌아갑니다.
              

              코드 수정·추가 테이블·스키마 변경은 되돌리지 않습니다. 기존 DB, 예측/해석 파일과 Grafana/Prometheus의 과거 기록도 지우지 않습니다. 초기화는 내구성 해결책이 아니라 반복 실험을 위한 정리입니다.
              



              

              도중 실패하면 백업·진행 기록을 보존하고 중단합니다. 오류를 확인하기 전 반복해서 누르지 마세요.
